# 《温泉小镇复兴》产品结构设计稿
## Merge + Narrative + Town Restoration + Light Management
### V0.3

> 项目类型：女性向 Cozy 手游  
> 核心玩法：Merge + 剧情 + 小镇修复；游客、店铺经营、居民系统按 S2–S4 分季逐步加入  
> 视觉方向：2D 精致人物立绘 + 低多边形 3D 小镇经营界面  
> 目标市场：日本优先，兼顾东亚与欧美女性休闲玩家  
> 核心情绪价值：治愈、成长、关系、重建、四季、生活感

---

# 1. 一句话定位

> **玩家来到一座逐渐衰落的温泉小镇，通过合成、完成居民委托、修复建筑、经营店铺和推进人物故事，让整个小镇重新热闹起来。**

---

# 2. 产品核心结构

本项目采用“双层游戏结构”。

## 2.1 2D 主循环层

负责：

- Merge
- 订单
- 剧情
- NPC 对话
- 章节任务
- 小型互动
- 资源生产

关键词：

> 高频、轻操作、碎片时间、剧情推进

## 2.2 3D 小镇层

3D 小镇从第一季就存在，但功能深度按 Season 逐步开放。

### S1：修复与可视化
- 建筑修复
- 建筑外观阶段变化
- 少量环境 NPC
- 小镇冷清 → 重新亮灯

### S2：游客
- 游客类型
- 游客需求
- 小镇满意度
- 游客流量可视化

### S3：店铺经营
- 店铺入驻选择
- 店铺升级
- 轻经营属性
- 商店街差异化

### S4：居民
- 新居民迁入
- 住宅与公共服务
- Residents / Visitors 双指标
- 居住与旅游之间的平衡

关键词：

> 长期目标、成长反馈、可视化、逐季解锁、轻经营

# 4. 玩家长期目标

不是简单“升到 100 级”，而是：

> **让一座濒临衰落的温泉小镇重新成为有人居住、有人工作、有人旅行、有人留下故事的地方。**

长期成长分为：

1. 小镇复兴
2. 角色关系
3. 店铺经营
4. 图鉴收集
5. 四季活动
6. 剧情推进
7. 个性化装饰

---

# 5. 世界观设定

地点：一座架空的日本山间温泉小镇。

特点：

- 曾经是知名温泉町
- 因交通线路改变、人口外流而衰败
- 老店陆续关闭
- 年轻人口减少
- 旧车站停运
- 小镇仍保留完整的街道、浴场和自然资源

玩家扮演：

> 一位因工作倦怠离开大城市的年轻女性，被地方振兴组织邀请，来到这里参与为期一年的“小镇复兴计划”。

这样避免“祖母遗产”“突然继承旅馆”等高频套路，玩家身份更主动。

---

# 6. 第一季主线目标

第一季核心目标：

> **让小镇重新举办已经停办多年的夏祭。**

需要逐步恢复：

- 车站入口
- 商店街
- 公共浴场
- 和菓子店
- 老旅馆「月见庄」
- 神社
- 河岸
- 夏祭广场

最终，小镇重新亮起灯笼。

---

# 7. 第一季章节结构

第一季 10 章。章节剧情细节以《S1 Story Outline》为准，本节只列每章的修复对象与解锁内容（与 S1 Outline §13 保持一致）。

> S1 系统边界：只开放 Merge + 修复 + 剧情。章节中出现的"游客""营业"只作为剧情结果与 3D 表现，不开放游客经营、店铺经营或居民系统。

| 章节 | 标题 | 主要修复 / 场景 | 解锁 |
|---|---|---|---|
| Ch1 | 最后一班车 | 项目办公室、站牌、千鹤堂门面 | Merge Board、小镇地图、基础修复、和菓子压模（试玩） |
| Ch2 | 三年没开门的店 | 千鹤堂制作台、旧模具 | 店铺修复、食材链基础、NPC 委托订单 |
| Ch3 | 没有客人的温泉 | 公共浴场、温泉管线 | 公共设施修复、调温小游戏；浴场重新冒出稳定蒸汽，出现少量老年 NPC |
| Ch4 | 和菓子的味道 | 千鹤堂（找回配方） | 和菓子进阶互动（调色 / 压纹 / 配比）、茶点链、礼物基础 |
| Ch5 | 不想回来的人 | 旧食堂、小型厨房（商店街后段开放） | 料理小游戏、夜间地图 |
| Ch6 | 梅雨季 | 浴场屋顶 / 商店街排水 / 河岸仓库（三选一，河岸开放） | 天气事件、轻量优先级选择 |
| Ch7 | 那间老旅馆 | 月见庄大厅、样板客房、小庭院 | 旅馆区域、室内修复（旅馆以剧情方式"3 间房试营业"，不开放旅馆经营） |
| Ch8 | 夏祭还能回来吗？ | 神社参道、夏祭广场 | 节庆链、布局互动（挂灯笼 / 摊位布局） |
| Ch9 | 台风 | 全镇防灾准备 | 限时优先级事件、多角色协作 |
| Ch10 | 灯亮起来的夜晚 | 夏祭会场全镇布置 | 拍照强化、S2 预告 |

第一季结尾表现：

- 整个 3D 小镇进入夜间节庆状态
- 商店街亮灯，浴场有蒸汽，月见庄三间客房亮灯
- 河岸灯笼、神社参拜人流、烟花
- 夏祭按居民决定"缩小规模"举办，不追求所有商店全部营业

第一季结束。

# 8. S1–S4 基础成长四部曲

本项目的 Content Season 与现实季节活动分离。

> **Content Season = 主线故事与系统解锁进度**  
> **Calendar Season = 春 / 夏 / 秋 / 冬的 LiveOps 与视觉活动**

两者不能绑定死。玩家无论当前处于哪个主线 Season，都可以参与现实时间对应的樱花、夏祭、红叶、正月等活动。

---

## S1：重新亮灯

核心问题：

> **这座小镇还能重新活起来吗？**

唯一新增核心系统：

> **Merge + 修复 + 剧情**

玩家主要做：

- 完成居民请求
- Merge 生产修复物品
- 修复车站、浴场、和菓子店、旅馆、神社等核心建筑
- 推进第一批居民故事
- 让停办七年的夏祭重新举行

3D 小镇功能保持轻量：

- 查看小镇
- 点击建筑
- 看修复前后变化
- 少量 NPC 走动
- 不做正式游客经营
- 不做店铺经营数值
- 不做居民人口系统

S1 结尾视觉目标：

> **街灯亮了、店门开了、夏祭回来了。**

---

## S2：有人来了

核心问题：

> **当外面的人真的开始来到这里，小镇准备好了吗？**

本季只新增一个核心系统：

> **Visitor System / 游客系统**

新增内容：

- 游客类型
- 游客偏好
- 游客满意度
- 游客容量
- 小镇问题反馈
- 3D 游客流量可视化

游客类型可包括：

- 情侣
- 家庭
- 摄影游客
- 温泉游客
- 美食游客
- 背包客

玩家第一次通过数据看到：

```text
本周游客：328
满意度：★★★★☆
主要抱怨：夜间活动不足
```

系统本身只负责告诉玩家“缺什么”，解决方式仍通过：

> Merge → 任务 → 修复 / 改善

不在 S2 引入复杂财务、员工排班和库存。

剧情主题：

> **被看见以后。**

小镇过去担心没人来，现在开始面对“人来了之后”的新问题。

---

## S3：店开起来了

核心问题：

> **热闹起来以后，这条街应该变成什么样？**

本季只新增：

> **Light Shop Management / 轻店铺经营与入驻系统**

核心玩法：

- 空置店铺出现候选经营者
- 玩家从多个方案中选择入驻者
- 店铺可升级 3–4 阶段
- 店铺外观在 3D 小镇中明显变化
- 不同店铺改变游客构成和小镇属性

例如同一间空铺可选择：

```text
咖啡馆 → 年轻游客 + / Revenue +
陶艺工房 → Culture ++
二手书店 → Comfort + / 停留时间 +
```

经营指标继续保持轻量：

- Popularity
- Revenue
- Culture
- Comfort

禁止在本季加入：

- 员工工资表
- 复杂库存
- 采购模拟
- 细粒度财务报表

本季开始形成：

> **“我的雾见町”**

不同玩家的小镇可以出现轻度差异。

---

## S4：有人留下了

核心问题：

> **这里能不能重新成为适合人生活的地方，而不只是一处旅游目的地？**

本季只新增：

> **Resident System / 居民与人口系统**

首次正式区分：

```text
Visitors 游客
Residents 居民
```

新增：

- 空置住宅修复
- 新居民迁入
- 居民满意度
- 基础公共服务
- 居住与旅游之间的轻度取舍

典型选择：

```text
一栋旧建筑

A. 改民宿
→ Visitors +++
→ Revenue ++

B. 改住宅
→ Residents ++
→ Community ++
```

可逐步开放：

- 民居
- 小型公寓
- 共享工作室
- 诊所
- 托儿空间

S4 结尾不需要更大的庆典。

推荐情绪高潮：

> 旧车站恢复周末停靠。一家三口拖着行李下车，他们不是来旅游，而是搬来生活。

最后显示：

> **Residents +3**

---

## S5 之后

S1–S4 完成后，核心基础系统已经齐备：

> Merge + Story + Restoration + Visitors + Shops + Residents

S5 起不再要求每季增加“大系统”，而以内容扩展为主：

- 新区域
- 新人物
- 新行业
- 邻近乡镇
- 湖区 / 茶山 / 旧校舍
- 新长期故事

避免产品长期陷入“每个 Season 都开发一个新游戏”的问题。

# 10. Merge 设计原则

禁止：

- 长时间纯刷合成
- 高级物品等待时间过长
- 玩家不知道合成物用途

推荐：

每一个 Merge 目标必须对应一个明确的小镇事件或人物需求。

例如，不是“合成 Level 7 Hammer”，而是“修好浴场屋顶需要高级维修工具”。

---

# 11. 小型互动玩法

为了避免整个游戏变成“Merge + 看剧情”，加入 10～30 秒轻互动。

S1 只做 6 个小游戏模板，各章的互动都是这些模板换素材（与 S1 Outline §14“小游戏 4～6 种”一致）：

| 模板 | 操作 | 覆盖的 S1 互动 |
|---|---|---|
| 清扫 | 滑动清除 | 擦灰、清排水口 |
| 归位 | 拖动物品到位置 | 整理办公室 / 客房、搬运物资、摊位布局 |
| 料理制作 | 选择 + 按压 + 摆放 | 和菓子压模 / 调色 / 压纹 / 配比、料理切配 / 火候 / 装盘 |
| 调温 | 滑块控制 | 准备温泉 |
| 修理 | 找点 + 点击正确零件 | 找漏点、修招牌、加固屋顶 |
| 挂灯笼 | 按顺序布置 | 挂灯笼、夏祭布置 |

这些小游戏强调参与感，不追求高难挑战。

# 15. 第一批建筑

> 每栋建筑分“S1 功能”和“后续季功能”。S1 只实现 S1 功能；后续季功能只在数据模型里预留字段。

## 15.1 旧车站
S1 功能：
- 新手区、小镇入口
- 修复站牌、开放候车室

后续季功能：
- 游客入口、提升游客上限（S2）
- 小站重新停靠（S4）

升级：
- 破旧站牌
- 修复候车室
- 小站重新运营

## 15.2 公共浴场
S1 功能：
- 社区公共空间、调温小游戏
- 修复后出现老年 NPC、夜间蒸汽与灯光

后续季功能：
- 提升游客满意度（S2）
- 产生温泉收益（S3）

升级：
- 基础浴池
- 室内浴池
- 露天浴池
- 景观温泉

## 15.3 和菓子店「千鹤堂」
S1 功能：
- 产生角色委托订单
- 解锁食材链 / 茶点链中的和菓子段
- 和菓子小游戏

后续季功能：
- 节庆期间收益提升（S3）

## 15.4 老旅馆「月见庄」
S1 功能：
- 第一季最大单体修复项目（Ch7）
- 3 间客房试营业（剧情与亮灯表现）

后续季功能：
- 接待过夜游客、游客容量（S2）
- 住宿收益、长期客人剧情（S3）

## 15.5 茶屋
S1 功能：
- 仅作为商店街后段外观建筑（未营业）

后续季功能：
- 提升游客停留时间（S2）
- 空铺入驻候选（S3）

## 15.6 神社
S1 功能：
- 夏祭核心建筑（Ch8 起开放）
- 解锁季节活动

后续季功能：
- 提升小镇 Culture 属性（S3）

# 16. 建筑升级逻辑

每个建筑建议 3～5 个阶段。

例如公共浴场：

```text
废弃
↓
修复
↓
重新营业
↓
扩建
↓
特色温泉
```

每升级一次必须：
- 外观明显变化
- 功能增加
- NPC 行为变化
- 游客数量变化（S2 起；S1 只表现 NPC 数量与灯光变化）

---

# 17. 小镇经营数值

S1 只显示一个数值：

- 雾见町复兴度（由修复进度计算，First Hour 中首次出现）

S2 起逐步加入，核心数值控制在少量：

- Popularity：小镇人气
- Comfort：舒适度
- Culture：文化魅力
- Revenue：经营收入
- Visitors：游客数量

不要加入大量员工工资、复杂供需和过多资源类型。

---

# 18. 游客系统（S2 解锁）

S1 只表现少量剧情游客，不开放正式游客经营。

S2 起正式加入：

- 游客数量
- 游客类型
- 游客偏好
- 满意度
- 容量
- 主要抱怨 / 需求

游客类型：

- 普通游客
- 情侣
- 家庭
- 老年游客
- 年轻背包客
- 摄影游客
- 美食游客
- 温泉爱好者

不同游客偏好：

- 温泉
- 美食
- 景色
- 文化
- 节庆

S2 的游客系统只解决一个问题：

> **让玩家看到自己修复的小镇真的开始被人使用。**

不在 S2 加入复杂财务与店铺经营。

# 19. 店铺经营系统（S3 解锁）

S3 才正式开放店铺入驻和轻经营。

核心：

- 空铺候选经营者
- 入驻选择
- 3–4 阶建筑升级
- 店铺属性
- 3D 外观变化

保持轻量，不引入复杂员工、库存和财务模拟。

---

# 20. 居民系统（S4 解锁）

S4 才正式加入 Residents。

核心：

- 新居民迁入
- 住宅修复
- 居民满意度
- 基础公共设施
- Visitors 与 Residents 的轻度取舍

本系统的情绪目标是：

> **让玩家第一次感受到“有人不是来玩，而是愿意在这里生活”。**

# 24. 剧情与经营联动

剧情必须真正影响小镇。

例如：

> 年轻厨师决定留下。

结果：

- 餐馆重新开业
- 新料理链解锁
- 夜间游客增加
- 新 NPC 出现

这样剧情不是“看完就结束”，而是改变世界状态。

# 36. 第一小时体验

详细设计以《First Hour Flow》为准，第一小时 = Ch1 全部：

- 0～8 分钟：抵达小镇、清理项目办公室
- 8～16 分钟：第一次 Merge、修站牌
- 16～25 分钟：春江出现、自由查看小镇
- 25～40 分钟：千鹤堂门面修复
- 40～48 分钟：和菓子小游戏、莲出场
- 48～60 分钟：千鹤没有被“解决”、夜景、“森川”悬念

# 40. 产品差异化

与传统 Merge Story 游戏相比，本项目差异为：

1. 真正可见的小镇变化：不是只修一个房间。
2. 3D 经营层：玩家能看到小镇“活起来”。
3. 日本四季与地方文化：不是简单换皮。
4. NPC 剧情影响世界：角色留下、离开、开店都会改变地图。
5. 小型真实互动：玩家不是只在 Merge Board 上操作。

---

# 41. 产品核心情绪

需要始终围绕：

- 被需要
- 被记住
- 有归属
- 慢慢变好
- 人与人重新连接
- 一个地方重新有生命

避免：

- 高频狗血
- 连续背叛
- 过度豪门冲突
- 强犯罪悬疑

可以有冲突，但总体应是：

> **温暖、治愈、带一点生活的遗憾。**

---

# 42. 最终产品定义

> **《温泉小镇复兴》是一款面向女性与 Cozy 玩家群体的 Merge + Narrative + Town Restoration 手游。玩家通过合成、完成居民委托和推进人物故事，逐步修复一座衰落的温泉小镇；后期通过低多边形 3D 经营系统管理建筑、游客、装饰与季节活动，让整个小镇真正从冷清走向繁荣。**
